# Current LLM and CLI contract

Sophie uses one shared `SophieRuntime` in the CLI, HTTP API, playground, and Promptfoo provider. The model's first Responses request returns a strict `TurnUnderstanding` object: intent, approval/denial/uncertainty, community-local date and time, contact fields, and canonical fact keys. The model is instructed to interpret the latest caller turn in context. The application never treats model output as a backend result or as permission to skip a required readback.

The policy calls typed tools itself after validating the model's plan. Fact keys must exist in the canonical registry. Availability is checked before asking for booking approval and again inside the transactional write. Contact and action details are read back; unclear or changed approval does not write. Every claimed write is verified against persisted SQLite state. Cancellation now requires its own approval turn even when the caller gives a known tour ID. Invalid or missing model interpretation asks for clarification and cannot trigger a write. There is no regex/keyword fallback for caller intent, consent, dates, contact, or fact selection. Regex remains only for structured-format checks such as `HH:MM`, generated IDs, phone/email syntax, and mailing-address syntax.

Each caller turn uses one Responses request for interpretation. The policy composes spoken facts and action receipts from verified service results. A previous optional second model call could rewrite a correct fact answer to include a false booking claim; that call was removed. Unknown facts retain deterministic uncertainty wording, and write outcomes use deterministic receipts. This closes the tested false-confirmation path. The current live evaluation measures interpretation and speech on its declared cases.

The Python SDK adapter uses `responses.create`, `store=False`, strict `text.format` for interpretation, and no automatic SDK retries. `OPENAI_MODEL` selects the model (default `gpt-6.1-sol`). `OPENAI_API_KEY` is required for live use. Each model response now records usage and cache details to a local ignored ledger, with a published-rate estimate when the price and response usage are complete; failures are unpriced attempts. The November 13, 2026 local live evaluation passed 42/42 final cases under prompt version `sophie-semantic-v4`; the separate noisy suite is documented in the README. Fake-client tests verify typed interpretation, persisted effects, safe failure, and that model phrasing cannot replace verified speech. Actual monetary spend still requires the account's billing data.

The CLI accepts an optional `--clock` for a fixed reproducible sandbox. A new sandbox without that option uses an advancing `America/New_York` clock. `--offline` exists only for diagnostics; without a model Sophie cannot interpret language or execute caller-requested actions. `/state` and `/events` inspect persisted tours and redacted trace events. Local SQLite rows retain caller text and contact until deleted by the operator.
